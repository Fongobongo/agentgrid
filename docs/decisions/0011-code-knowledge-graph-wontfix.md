# ADR 0011: Code knowledge graph — решение по полной версии (#12)

Status: **Declined (until trigger fires)**. Accepted: the minimal slice only.

## Контекст

Конкурентный анализ (#12, colbymchenry/codegraph) предлагал pre-indexed
code knowledge graph, синкающийся на изменения и кормящий контекст
агентов. Этап 1.13 приземлил минимум: `ag index` (paths/symbols/imports,
zero-dep), кэш по commit-hash, opt-in digest в промпт
(`AGENTGRID_REPO_INDEX=1`).

Открытым оставался вопрос полной версии: живой граф с авто-синком.

## Решение

Полную версию **не строим**, пока не сработает триггер (ниже). Причины:

1. У адаптеров (Claude Code / Codex / OpenCode) уже есть встроенный
   codebase awareness — они индексируют репо сами. Свой парсер будет
   хуже и дороже в поддержке.
2. Digest в system prompt стоит токенов на *каждой* попытке — прямо
   противоречит #14 (token budget). Auto-sync графа решает это лишь
   частично (digest всё равно надо доставлять).
3. Живой граф требует инфраструктуры: индексатор, инкрементальный
   sync, хранилище. Для MVP-оркестратора это новый сервис, а не фича.

Плоская альтернатива уже есть: shared memory (1.12) несёт
долгоживущий контекст командами/вердиктами, а не AST.

## Триггер пересмотра

Вернуться, если: (а) реальный агент систематически не находит нужные
файлы в крупных монорепах (наблюдаемый фейл, не гипотеза), или (б)
доминирующий адаптер откажется от встроенной индексации. Тогда первый
шаг — MCP-сервер поверх gRPC-free индекса, не свой парсер.

## Последствия

- `ag index` и digest-injector остаются как есть (opt-in, без SLA).
- Roadmap-строка "#12" закрыта как WONTFIX; roadmap не должен
  возвращать её без одного из триггеров выше.
