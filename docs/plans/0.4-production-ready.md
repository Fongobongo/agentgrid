AgentGrid v0.4 переводит платформу из "MVP" в "Production Ready". Основные улучшения:
- Kubernetes deployment (Helm charts) вместо Docker Compose
- Production monitoring & alerting (Prometheus + Grafana)
- Batched task assignment для масштабируемости
- Расширенная sandbox isolation (Podman containers)
- External integrations (GitHub webhooks, Slack notifications)
- Multi-tenant support (namespace isolation)

## Этап 2: Performance Improvements (3–4 дня)

### 2.1 Batched Assignment

**Проблема:** Single-writer gate causes serialization bottleneck under high concurrency

**Solution:** Batch task assignment in single transaction

```rust
// New scheduler method
pub async fn assign_batch_assignments(
    state: Arc<AppState>,
    nodes: &[NodeInfo],
    batch_size: usize,
) -> Result<Vec<TaskAssignment>> {
    let mut tx = state.store.begin_immediate_transaction().await?;
    
    // Select all eligible tasks in one query
    let eligible_tasks = select_eligible_tasks(&mut tx, batch_size).await?;
    
    // Assign to nodes round-robin by capacity
    let assignments = eligible_tasks.into_iter()
        .zip(nodes.iter().cycle())
        .take(batch_size)
        .map(|(task, node)| create_assignment(&mut tx, task, node))
        .collect::<Result<Vec<_>>>()?;
    
    tx.commit().await?;
    Ok(assignments)
}
```

#### Metrics expectations:
| Scenario | Current (v0.3) | Target (v0.4) | Improvement |
|---|---|---|---|
| 100 nodes, 1000 tasks | poll_avg=2.1s | poll_avg=200ms | 10x faster |
| assign_p99 latency | 29.5s | 2.0s | 15x faster |
| write_lock_failures | 0 | 0 | maintained |

### 2.2 Read Replica Offload

**Problem:** All read queries hit primary database

**Solution:** Deploy PostgreSQL read replicas for task/event queries

```yaml
database:
  primary:
    host: "agentgrid-primary.internal"
  replicas:
    - host: "agentgrid-replica-1.internal"
    - host: "agentgrid-replica-2.internal"
  
  routing:
    reads_from_replica: true
    read_consistency: session  # Strong consistency for writes only
```

#### Query routing strategy:
```sql
-- Write operations go to primary
BEGIN IMMEDIATE;
INSERT INTO tasks (...) VALUES (...);
COMMIT;

-- Read operations use replica (eventually consistent)
SELECT * FROM tasks WHERE status = 'queued' LIMIT 50;
```

### 2.3 Redis Cache Layer

**Cache layers:**
1. **Node registry** — TTL 30s, invalidated on heartbeat
2. **Task assignments** — Short-lived (1h)
3. **Artifact URLs** — Pre-signed S3 URLs (15m TTL)

```rust
use redis::Client;

struct CachedState {
    client: Client,
    node_ttl_secs: u64,
    assignment_ttl_secs: 3600,
}

impl CachedState {
    pub async fn get_node(&self, node_id: &str) -> Option<NodeInfo> {
        self.client.get_cache(format!("node:{node_id}")).await
    }
    
    pub async fn cache_assignment(&self, task_id: &str, assignment: &Assignment) {
        self.client.set_cache_with_ttl(
            format!("assignment:{task_id}"),
            assignment,
            self.assignment_ttl_secs,
        ).await;
    }
}
```

### 4.3 Artifact Upload to S3

**Features:**
- Automatic upload on completion
- Versioning enabled
- Lifecycle policies (auto-delete after 30 days)

```rust
struct S3ArtifactUploader {
    client: aws_sdk_s3::Client,
    bucket: String,
    prefix: String,
}

impl S3ArtifactUploader {
    async fn upload_artifact(&self, attempt_id: &str, name: &str, content: &[u8]) 
        -> Result<String>
    {
        let key = format!("{}/{}/{}", self.prefix, attempt_id, name);
        
        self.client.put_object()
            .bucket(&self.bucket)
            .key(&key)
            .body/aws_sdk_s3::types::Blob::new(content.to_vec()))
            .send()
            .await?;
            
        Ok(format!("s3://{}/{}/{}", self.bucket, self.prefix, key))
    }
}
```

## Этап 5: Documentation & Migration (2 дня)

### 5.1 Upgrade Guides

#### From v0.3 to v0.4:
```markdown
## Breaking Changes

1. **Storage backend migration**
   - SQLite → PostgreSQL (recommended)
   - Migration script provided
   
2. **Configuration format**
   - YAML → JSON with schema validation
   - Environment variables deprecated in favor of ConfigMaps

3. **API changes**
   - `/v1/tasks/:id/logs` → `/v1/tasks/:id/events?after_ingest=N`
   - Authentication now requires OAuth2 tokens

## Migration Steps

1. Backup existing data
   ```sql
   sqlite3 control-plane.db ".backup 'backup-v0.3.sql'"
   ```

2. Install PostgreSQL
   ```bash
   helm install postgres bitnami/postgresql --set persistence.enabled=true
   ```

3. Run migration tool
   ```bash
   agentgrid-migrate from-sqlite control-plane.db postgresql://...
   ```

4. Deploy new components
   ```bash
   helm upgrade agentgrid ./charts/agentgrid \
     --set database.type=postgresql \
     --set monitoring.enabled=true
   ```

5. Validate everything works
   ```bash
   kubectl rollout status deployment/agentgrid-control-plane -n agentgrid
   kubectl get pods -n agentgrid
   ```
```
