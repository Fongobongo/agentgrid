# План доведения agentgrid до рабочего MVP 0.2

Составлен 2026-08-06 по итогам полного ревью кода. Приоритеты: сначала то,
без чего проект бесполезен (реальный адаптер + зелёный CI), потом качество
жизни оператора. Каждый пункт имеет критерий приёмки — пункт закрывается
только при его выполнении.

Легенда: `[ ]` не сделано, `[x]` сделано и проверено.

## Этап 0. Починить контроль качества (фундамент, 2–3 дня)

Без этого этапа все остальные правки будут гнить незамеченными: e2e-скрипты
месяцами были сломаны и никто не заметил.

- [ ] 0.1. Запустить `tests/e2e/run.sh` локально от и до, зафиксировать реальный
  статус (сейчас после фикса парсинга ListResponse он должен проходить;
  проверить на чистой машине/контейнере).
  - Критерий: `E2E OK` в выводе, без ручных вмешательств.
- [ ] 0.2. Ввести e2e в CI (GitHub Actions): build образов → `tests/e2e/run.sh`.
  - Критерий: PR не мержится без зелёного e2e.
- [ ] 0.3. Ускорить `race_ack_lease_100_iterations_no_drift`: 100 итераций
  занимают ~21 мин. Варианты: `#[ignore]` + отдельная nightly-джоба, либо
  снизить до 10 итераций в обычном прогоне (рейс покрывается и на 10).
  - Критерий: `cargo test --workspace` < 5 минут.
- [ ] 0.4. Изолировать тесты от чужих процессов: `validation_timeout_kills_forked_child_tree`
  использует `pgrep -f sleep` и ловит посторонние процессы системы.
  Заменить на учёт по PID-группе/cgroup теста или уникальному маркеру команды.
  - Критерий: тест проходит при одновременно запущенном `sleep 500` в системе.
- [ ] 0.5. Чистка temp-файлов в тестах: после прогона в `/var/tmp` остаются
  тысячи `ag-*` файлов/dirs. Добавить cleanup в Drop/guard тестовых хелперов.
  - Критерий: после `cargo test --workspace` в `/var/tmp` < 10 `ag-*` объектов.
- [ ] 0.6. Лимит времени CI-джобы + отчёт по самым медленным тестам

  - Критерий: видно топ-5 медленных тестов в логах CI.

## Этап 1. Реальный адаптер — главный недостающий кусок (1–2 недели)

Сейчас единственный адаптер — mock. Проект не выполняет настоящую работу.
Начать с одного адаптера (рекомендация: Claude Code CLI — стабильный
NDJSON/JSON выход и `--print` режим), остальные потом по тому же контракту.

- [ ] 1.1. Задокументировать точный контракт адаптера в `docs/adapters.md`:
  какие JSON-линии обязан выдавать адаптер (`log`/`tool_call`/`file_change`/
  `progress`/`result`/`error`), коды выхода, таймауты, поведение при SIGTERM.
  - Критерий: документ, по которому можно написать адаптер с нуля.
- [ ] 1.2. `crates/adapters`: реальный адаптер `claude-code` — обёртка над
  `claude -p` (stream-json), маппинг вывода в контрактные события.
  - Критерий: юнит-тесты на парсинг реальных сэмплов вывода (зафиксировать
    fixture-файлы).
- [ ] 1.3. node-daemon: запуск реального адаптера в worktree с перехватом
  разрешений (permission interception уже есть) и маскировкой секретов.
  - Критерий: ручной прогон одной задачи «создай файл X» через `ag task run`
    с реальным агентом завершается `succeeded`, артефакт/коммит на месте.
- [ ] 1.4. Таймауты и стоимость: проброс `timeout_secs` задачи в адаптер,
  учёт токенов/стоимости из stream-json в budget workflow.
  - Критерий: бюджет `max_tokens` реально обрывает задачу.
- [ ] 1.5. E2E с реальным агентом (за API-ключом, `#[ignore]` / nightly):
  - Критерий: nightly-джоба прогоняет одну реальную задачу на двух узлах.

## Definition of Done для MVP 0.2

Проект считается доведённым, когда одновременно верно:

1. CI зелёный: fmt, clippy, unit, e2e (mock) — на каждый PR.
2. Nightly зелёный: e2e с реальным агентом, нагрузочный тест тикера.
3. Новый оператор по README разворачивает стек и выполняет реальную задачу
   (не mock) на двух узлах за ≤ 15 минут.
4. Убийство control-plane и восстановление из бэкапа занимает < 5 минут
   без потери завершённых задач.
5. В UI можно выполнить весь цикл: создать задачу → одобрить разрешения →
   увидеть результат workflow — без CLI.
